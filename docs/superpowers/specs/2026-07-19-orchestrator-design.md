# Оркестратор ИИ-моделей — дизайн

Дата: 2026-07-19
Источник: `orchestrator-architecture.pdf` (техническая спецификация)

## 1. Цель

Единая CLI-команда, которая принимает задачу на естественном языке, сама
определяет её сложность и направляет в подходящий агентный каркас с подходящей
моделью. Экономическая задача — беречь лимит подписки Claude Pro: рутина уходит
на бесплатные/дешёвые модели через OpenRouter, Claude Code вызывается только там,
где дешёвые модели объективно не справляются.

## 2. Область реализации

Реализуется **полная лестница сразу** (решение пользователя, отличное от
поэтапного порядка из раздела 9 спеки): ручные префиксы уровней, эвристики,
LLM-классификатор и авто-эскалация с переносом контекста — всё в первом заходе.

Каркасы вызываются **реально** (`opencode` и `claude` через subprocess).
На момент написания `opencode` не установлен и `OPENROUTER_API_KEY` не задан —
пользователь ставит их сам. Поэтому точные команды каркасов вынесены в конфиг,
а отсутствие бинаря/ключа даёт понятную ошибку, а не трейсбек.

## 3. Стек и структура

Python 3.13, **только stdlib** в рантайме:
- `subprocess` — спавн каркасов, стрим потоков, коды выхода
- `urllib.request` — вызов OpenRouter (LLM-классификатор)
- `tomllib` — чтение `config.toml`
- `json` — JSONL-журнал
- `pytest` — dev-зависимость для тестов

Точка входа — консольная команда `orchestrator` (эквивалент `python -m orchestrator`).

```
orchestrator/
  __init__.py
  __main__.py     entry point
  cli.py          парсинг ввода (префикс/флаги/задача), подкоманды, вывод
  router.py       3 уровня классификации → RouteDecision(level, framework, models)
  runner.py       спавн opencode/claude, стрим, коды выхода, лимит шагов
  escalate.py     детекция провала, сборка контекста, рестарт на уровень выше
  budget.py       стоимость OpenRouter + счётчик окна Pro (эвристика по времени)
  journal.py      JSONL-запись решений и исходов
  config.py       дефолты + оверрайд из config.toml, dataclass-модели
config.toml       лестница моделей с фолбэками, команды каркасов, пороги
tests/
pyproject.toml
```

## 4. Лестница моделей (config.toml)

Каждый уровень — **список моделей-фолбэков**, а не жёсткий ID (состав free-тира
OpenRouter ротируется без предупреждения). Значения на июль 2026, могут устареть.

| Ур. | Модель (первичная)          | Цена вход/выход за 1M | Каркас       | Назначение                        |
|-----|-----------------------------|-----------------------|--------------|-----------------------------------|
| L0  | cohere/north-mini-code:free | $0 / $0               | opencode     | тривиальное: докстринги, формат   |
| L1  | poolside/laguna-m.1:free    | $0 / $0               | opencode     | простые правки в одном файле      |
| L2  | minimax/minimax-m3          | $0.60 / $2.40         | opencode     | основная рабочая лошадка          |
| L3  | moonshotai/kimi-k2.7-code   | ≈$0.95 / $4.00        | opencode     | долгие агентные сессии            |
| L4  | claude (Pro)                | подписка              | claude       | архитектура, сложные баги         |

Команды каркасов — шаблоны в конфиге, например:
- `opencode run -m {model} "{prompt}"`
- `claude -p "{prompt}" --max-turns {steps}`

(Точные флаги проверяются при установке каркасов; конфиг — единственное место правки.)

## 5. Поток одной задачи

1. **cli.py** разбирает ввод: явный префикс уровня (`/l0`..`/l4`), флаги
   (`--dry-run`, `--max-steps N`, `--test-cmd "..."`, `--no-commit-guard`),
   остальное — текст задачи. Подкоманды: `run` (по умолчанию), `rollback`, `journal`.
2. **Предохранитель:** проверка, что каталог — git-репо; обязательный
   чекпоинт-коммит текущего состояния перед запуском агента, чтобы откат был
   одной командой (`orchestrator rollback` = `git reset --hard <checkpoint>`).
   Без git — отказ. `--no-commit-guard` снимает требование (для отладки).
3. **router.py** классифицирует по возрастанию стоимости, останавливается на
   первом сработавшем уровне:
   - **Ур.1 — явное указание:** префикс переопределяет всё, роутер не думает.
   - **Ур.2 — эвристики** (мгновенно, бесплатно), ловят ~70%:
     - число затрагиваемых файлов через **ключевые слова + grep** по репозиторию
       (извлечь упомянутые в задаче имена/символы, grep, посчитать файлы);
     - словари: «вверх» (архитектура, миграция, развяжи, перепиши),
       «вниз» (переименуй, добавь тест, докстринг, отформатируй);
     - правка-по-образцу vs необходимость понять чужой код;
     - флаг «эта задача уже проваливалась на нижнем уровне».
   - **Ур.3 — LLM-классификатор:** остаток → самая дешёвая модель, промпт
     «оцени сложность от 1 до 5, ответь одной цифрой». Маппинг 1→L0 … 5→L4.
4. **runner.py** спавнит каркас: L0–L3 → `opencode` с моделью уровня (перебор
   фолбэков при недоступности), L4 → `claude`. Реальный subprocess, стрим
   stdout/stderr в консоль, лимит шагов передаётся флагом каркаса.
5. **escalate.py** — триггеры провала:
   - ненулевой код выхода каркаса;
   - превышен лимит шагов на задачу;
   - (опц.) тесты не прошли после прогона — если задана `--test-cmd`/конфиг;
   - зацикливание — best-effort: повторяющиеся одинаковые строки-вызовы в выводе.

   При провале собирается стартовый промпт: **журнал задачи** (исходная
   формулировка, изменённые файлы, вывод команд, попытки) + `git diff` текущего
   состояния. Файлы уже на диске — состояние восстановимо из репо. Задача
   перезапускается на уровень выше.
6. **budget.py**:
   - перед подъёмом на L4 проверяет окно Pro — счётчик L4-запусков в скользящем
     5-часовом окне (цикл Pro), пороги в конфиге. На исходе — предлагает
     подождать/очередь вместо сжигания остатка;
   - обратная эскалация: при исчерпании лимита задача уходит вниз с пометкой в
     журнале;
   - для OpenRouter суммирует стоимость (токены × цена уровня из лестницы).
7. **journal.py** дописывает одну JSONL-строку на решение: время, задача,
   выбранный уровень, основание (какой уровень классификатора сработал + причина),
   каркас, модель, исход, число шагов, стоимость, цепочка эскалаций.

## 6. Обработка ошибок

- `opencode` не установлен → понятная ошибка с подсказкой поставить, не трейсбек.
- `OPENROUTER_API_KEY` не задан → понятная ошибка перед вызовом OpenRouter/opencode.
- Модель уровня недоступна → следующий фолбэк; если все исчерпаны — эскалация/отчёт.
- Провал на L4 (верх лестницы) → стоп с отчётом, эскалировать некуда.
- Не git-репо → отказ запускать агента (предохранитель), подсказка `git init`.

## 7. Предохранители (раздел 7 спеки)

- Обязательный чекпоинт-коммит перед запуском любого агента; откат одной командой.
- Жёсткий лимит шагов на задачу (защита от зацикливания и выжигания квоты).
- Потолок стоимости на задачу — прерывание при превышении.
- Журнал решений как источник данных для калибровки порогов.

## 8. Тесты (TDD)

- `router` — решения при мокнутых grep/LLM (каждый уровень классификатора, маппинг 1–5→L).
- `journal` — round-trip записи/чтения JSONL.
- `budget` — счёт окна Pro (скольжение 5ч) и суммирование стоимости.
- `escalate` — детекция каждого триггера провала, сборка контекста (журнал + diff).
- `cli` — разбор префикса, флагов, подкоманд.
- `runner` — спавн через мок subprocess; понятная ошибка при отсутствии бинаря;
  перебор фолбэков.
- `config` — загрузка дефолтов и оверрайд из TOML.

## 9. Сознательные упрощения относительно спеки

- **Детекция зацикливания** и **«тесты не прошли»** зависят от того, что каркас
  печатает в неинтерактивном режиме. Зацикливание — best-effort (скан повторов в
  выводе); прогон тестов — через опциональную `--test-cmd`/конфиг, не автомагией.
  Надёжные триггеры эскалации (код выхода, лимит шагов) — основные.
- **Окно Pro** — эвристика по времени/счётчику (надёжного API нет), лимиты в конфиге.

## 10. Данные, требующие проверки перед стартом (раздел 11 спеки)

- Состав free-моделей на openrouter.ai/models (ротируется) — держим списком фолбэков.
- Актуальные цены L2/L3 и лимиты Claude Pro.
- Точный неинтерактивный CLI `opencode` и `claude` (флаги модели, шагов, print-режим)
  — вынесены в `config.toml`, правятся в одном месте.
